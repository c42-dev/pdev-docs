<Note>
**异步处理。** 创建提现时返回的是非终态状态（`pending` 或 `processing`）——最终结果始终通过 webhook 送达（`withdrawal.completed` 或 `withdrawal.failed`）。请以 webhook 为准；不要把创建接口的响应当作最终结果。

校验错误（余额不足、超出限额、数据无效）会在调用本身直接返回错误。
</Note>

## 发送队列

提现被受理后，会进入向支付机构发送的队列。大多数情况下会立即发送；在交易高峰期可能需要几秒到几分钟，等待期间提现保持 `processing` 状态。

- **按到达顺序。** 提现按创建顺序依次发送。
- **不存在的密钥代价高昂。** 每笔提现都会在 DICT 中查询目标 PIX 密钥，而巴西中央银行对这类查询设有限额——查询一个不存在的密钥所消耗的额度远高于一次成功的查询。当某个账户因密钥不存在或无效而累积多次拒绝时，其后续提现在队列中的优先级会降低，等待时间更长。请在发送前校验密钥，不要用提现来测试密钥是否存在。
- **密钥查询被暂停。** 如果机构提示查询限额已用尽，尚未发送的提现将在队列中等待，直到恢复为止。已经发送的提现可能以 `withdrawal_failed` 返回，金额退回余额。
- **最长期限。** 6 小时内仍无法发送的提现将失败（`withdrawal_failed`），预留金额退回余额。

无论哪种情况，最终结果都通过 webhook 送达。
